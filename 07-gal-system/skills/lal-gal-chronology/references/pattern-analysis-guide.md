## What Is a Pattern?

A pattern is a recurring behavior, condition, or dynamic observed across:
- Multiple time periods
- Multiple sources
- Multiple settings

A single incident is not a pattern. One source's allegation is not a pattern.
A pattern requires repetition and corroboration.

### Step 4 — Identify Corroboration Level

| Level | Definition |
|-------|-----------|
| **Single-source** | Only one source has reported this |
| **Multi-source — aligned** | Multiple sources report consistently; note if sources are independent |
| **Multi-source — mixed** | Sources conflict; note the conflict |
| **Record-corroborated** | Records independently confirm what sources reported |

### Step 5 — Connect to Child Impact

Every pattern must be connected to its impact on the child — or the absence of demonstrated impact must be noted.

> "This pattern has been associated with [specific child behavior, presentation, or statement] as reported by [source]."
> OR
> "The GAL identified no documented evidence that this pattern has directly affected the child to date. However, [potential concern]."

## Pattern Categories — Quick Reference

### Escalation Pattern
Same behavior occurring with increasing frequency or severity over time.
Documentation: Timeline the incidents. Note trend.

### Chronic Low-Level Pattern
Same behavior at consistent low level over extended period.
Documentation: Note duration and consistency. Assess cumulative impact.

### Triggered Pattern
Behavior occurs in response to specific circumstances (litigation events, transitions, etc.)
Documentation: Map behavior to triggering events. Assess predictability.

### Improvement Pattern (Protective Factor)
Prior concerning behavior that has demonstrably improved.
Documentation: Note what changed, when, and how change is documented.

### Contradictory Pattern
Sources describe behavior inconsistently — some report concern, others do not.
Documentation: Map sources to their accounts. Identify what could explain the difference.
